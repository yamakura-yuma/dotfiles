**判断に効いた原則。**
- **Laziness Protocol。** SMS や LINE は「来期に増えるかもしれない」段階なので、通知先の登録簿やクラス階層は作りませんでした。案 2 のリストも同じ理由で外しました。
- **Model the Domain。** 構造を足すのは、分岐や重複を実際に消せるときだけにしました。条件付きの通知先が Slack 一つしかない今は、素の関数が一番わかりやすい形です。
- **Boundary Discipline。** 環境変数の確認と失敗時の扱いを `notify_slack` の中に閉じました。`ship_order` は Slack が任意であることも、失敗しうることも知りません。
- **Test Behavior, Not Implementation。** テストは「呼ばれたか」ではなく、実際に送られた URL と JSON を具体的な値と完全一致で比べます。どのテストも環境変数を一度空にしてから設定するので、実行するマシンの `SLACK_WEBHOOK_URL` が混ざりません。
- **Prove It Works。** モックを使った単体テストに加えて、ローカルの HTTP サーバーへ本当に送って確かめました。確認用のスクリプトは `/tmp/arena-slack/e2e.py` にあり、コミットには入れていません。
