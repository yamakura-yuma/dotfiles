`export_csv` と `export_json` の重複をなくし、feature ブランチにコミットしました。呼び出し方は変わりません。出力もバイト単位で同じです（テストと差分チェックで確認済み）。来月 XML を足すときは `_rows(users)` を読んで文字列にする関数を 1 つ書くだけで、行の組み立て部分には手を入れずに済みます。

**変えた構造**
- `Row` という型が列の並び（id, name, joined, plan）を持ちます。CSV のヘッダも JSON のキーの順番もここから取ります。以前は列名のリストが 2 箇所にあり、XML を足すと 3 箇所になるところでした。
- `_rows(users)` が、非アクティブ行の除外、名前・日付・プランの整形、id 順の並べ替えを 1 箇所で持ちます。
- `export_csv` と `export_json` は、でき上がった行を書き出すだけになりました。`report.py` は 41 行から 39 行に減っています。

**進め方**
- 構造を変える前に、今の動きをテストで固定しました。もとの JSON テストは id の並びしか見ていなかったので、完全一致の比較に直しました。空の入力、カンマや引用符を含む名前、日本語の名前、日付が壊れた非アクティブ行も足しています。追加したテストはすべて旧実装でも通ります。
- 設計は architect スキルに従い、opus、sonnet、haiku に別々に案を出させました。3 案とも「行を作る関数を 1 つにし、形式ごとの関数は書き出しだけ」に行き着きました。違ったのは、行を型にするかどうかと、列名をどこに持つかです。
- 別の judge（sonnet）に採点させたところ、自分と同じく opus の案を推しました。ただし 4 モデルとも Claude なので、評価が一致したことの重みはそのぶん割り引いてください。
- opus の案のうち、呼び出し元が 1 つしかない中間関数 `_render_csv` と `_render_json` は、公開関数にインライン化しました。

**確認したこと**
- 旧実装で 4 種類の入力から出した CSV と JSON を保存し、新実装の出力と比べてバイト単位で一致しました。スクリプトは `/tmp/arena-export/golden.py`、比較元は `baseline.txt` です。
- `python3 -m unittest` は 5 件すべて通っています。
- 依存パッケージは増えていません。`typing.NamedTuple` は標準ライブラリです。

**コミット**
1. `e898564` 出力をバイト単位で固定するテスト。
2. `ee32d31` 日付が壊れた非アクティブ行を読み飛ばすことを固定するテスト。
3. `af1640e` 本体のリファクタ。

**判断したこと**
- CSV の書き出しを `csv.DictWriter` から `csv.writer` に変えました。judge はここを唯一のバイト差リスクとして挙げましたが、上の比較で一致しています。
- 形式名から関数を引く対応表や、Exporter の基底クラスは作っていません。今の形式は 2 つで、形式名で呼び分ける呼び出し元もないので、読む手間が増えるだけだと判断しました。XML は関数を 1 つ足せば済みます。

**変わったこと**
- 動作上の差が 1 つだけあります（コードを読んで推論したもので、未計測です）。id がなく、しかも日付も壊れている入力で、出る例外が `ValueError` から `KeyError` に変わります。旧実装は日付の解釈を先にしていましたが、新実装は id を先に読むためです。正しい入力の出力には影響しません。

**やらなかったこと**
- PR は作っていません。指示が「feature ブランチにコミット」だったためです。
- how スキルによる調査と interrogate スキルによる反論レビューも省きました。対象が 41 行のファイル 1 つで、3 案がすでに同じ形に収まっていたからです。
- 判断の記録は `/tmp/arena-export/` に手元の記録として残しただけで、コミットしていません。

**方針に使った原則**
- Model the Domain。列の並びを `Row` 型に持たせ、列名リストの重複を消しました。
- Laziness Protocol と Minimize Reader Load。1 箇所からしか呼ばれない `_render_*` を消し、対応表も作りませんでした。
- Test Behavior, Not Implementation。id しか見ていなかった JSON テストを完全一致の比較に直しました。
- Prove It Works。旧実装と新実装の出力を比べるスクリプトを書いて実行しました。
- Sequence Work into Verifiable Units。テストで固定するコミットを先に置き、本体の変更をその後にしました。
