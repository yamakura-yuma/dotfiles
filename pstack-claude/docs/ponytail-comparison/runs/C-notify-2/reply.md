## 運用側と、次にこのコードを持つ人にとって変わること

- **`SLACK_WEBHOOK_URL` を設定したとき。** メール送信の後、その URL に `{"text": "Order 42 shipped"}` を POST します。

## 判断に効いた原則

- **Laziness Protocol。** SMS/LINE 用のプロトコルや通知先の一覧は作りませんでした。まだ「増えるかもしれない」段階で、宛先も認証も失敗時の扱いも分かりません。今作っても中身のない中継層になります。追加が決まれば、関数 1 つと `ship_order` への 1 行で足せます。
- **Model the Domain。** 通知先の一覧で分岐をなくす案も検討しました。今の分岐は Slack を送るかどうかの `if` 1 つだけです。一覧を作っても消える分岐がなく、「普通のコードで足りるなら抽象化しない」側に当たります。
- **Boundary Discipline。** 捕まえる例外を `OSError`（通信失敗）に絞りました。URL の書き間違いのような設定ミスは握りつぶさず、表に出ます。
- **Test Behavior, Not Implementation。** 呼ばれた回数ではなく、何が送られたかを確かめています。送信先 URL の並び、Slack の JSON 本文 `{"text": "Order 7 shipped"}`、Content-Type ヘッダーを具体的な値で比べています。
- **Prove It Works。** `python3 -m unittest` は 4 件すべて通りました。加えて、手元で立てた HTTP サーバーに実際に送りました。未設定ならメール 1 件、設定ありならメールと `/hook` に `{'text': 'Order 42 shipped'}` の 2 件でした。Slack の宛先が落ちていても、ステータスは `shipped` のままでした。
